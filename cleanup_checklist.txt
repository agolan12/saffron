6. Not dead code, but found while looking -- worth fixing
==========================================================================

[ ] BUG: stage 2 of supconloss_test_old.py crashes.
    freeze_backbone(model) (line 449) is given the MicrogliaCNN, but the
    function reads `model.cnn.cnn1` / `model.cnn.cnn2` (lines 215-218).
    MicrogliaCNN has `cnn1` and `cnn2` directly and no `.cnn` attribute
    (only the embedding wrapper has `.cnn`), so this raises AttributeError
    after stage 1 finishes. Consistent with the logs: the one run that
    reached "Stage 2" (output_supconloss_test_gyrified_lr005.out) never
    printed "Backbone frozen" or "Generating final embeddings".
    Fix: pass embedding_model, or change the function to use model.cnn1 /
    model.cnn2.

[ ] The freeze_backbone docstring and print mention "fc1 and fc2", but
    MicrogliaCNN only has fc1 (two Linear layers inside one Sequential).

[ ] `--epochs` only controls stage 2. Stage 1 is hard-coded to 100 epochs
    (line 433), so `--epochs=100` in the SLURM files means 100 + 100.

[ ] `-w/--weights` help text says "store or load", but the script never
    loads weights; it only saves to that path each epoch.

[ ] MicrogliaCNN defaults to num_classes=6, while the SupCon script trains
    on 3 labels (mice, rat, gyrified). It runs, but three output units are
    never a correct answer.

[ ] 30 of the error logs end in "CUDA error: CUDA-capable device(s) is/are
    busy or unavailable" -- those array tasks never trained.
